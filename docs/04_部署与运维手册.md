# 部署与运维手册

## 1. 服务组件

生产部署至少包含 Nginx、FastAPI API、Agent Worker、事件处理 Worker、MySQL、PostgreSQL/pgvector、Redis 和集中式日志。各组件使用独立账号、网络和健康检查。

## 2. 启动检查

1. 检查环境变量和密钥来源。
2. 检查 MySQL、PostgreSQL、Redis 连通性。
3. 执行数据库迁移并确认版本。
4. 启动 API 和 Worker，检查 `/api/health`。
5. 使用受限账号验证登录、设备查询、订单查询和审批链路。

## 3. 监控指标

监控 API 延迟、错误率、登录失败、设备在线率、故障工单积压、订单失败率、Agent 工具失败率、审批等待时长、队列积压和数据库连接池。P1 故障需触发值班告警。

## 4. 备份与恢复

MySQL 和 PostgreSQL 执行每日全量、持续增量备份，备份加密并保留异地副本。每月进行恢复演练，验证用户、订单、设备事件、审批和审计数据完整性。

## 5. 故障处理

API 异常先检查健康接口、应用日志和数据库连接；事件积压检查 Redis 和 Worker；设备大面积离线时冻结自动批量动作并转人工审批；Agent 服务不可用时保留人工运营接口和工单流程。

## 6. 回滚

应用回滚使用上一版本镜像；数据库变更必须提供向后兼容迁移和回滚脚本。涉及订单、退款和审批的数据变更不得直接删除，采用状态修正和审计补偿。

## 7. Netlify 部署（演示模式）

本项目支持以 Netlify 静态站点 + Serverless Function 的形式零数据库部署，用于演示与验收。

### 7.1 部署形态

- 静态资源：`static/` 目录（前端 HTML/CSS/JS）由 Netlify CDN 托管。
- API：FastAPI 应用经 `mangum` 包装为 Netlify Function（`netlify/functions/api.py`），`/api/*` 由 `netlify.toml` 中的 redirect 规则转发到 `/.netlify/functions/api`。
- 数据：`DEMO_MODE=true` 使用进程内存储与种子数据，无需 MySQL/PostgreSQL/Redis。

### 7.2 部署步骤

1. 将仓库推送到 Git 并导入 Netlify（Build 配置自动读取 `netlify.toml`）。
2. 确认构建设置：`PYTHON_VERSION=3.12`，构建命令 `pip install -r requirements.netlify.txt -t netlify/functions`，发布目录 `static`。
3. 在 Netlify 环境变量中设置 `DEMO_MODE=true`（`netlify.toml` 未硬编码该变量，函数入口默认值亦为 true）。
4. 部署完成后访问站点根路径进入登录页，`/api/health` 应返回 `status: ok`。

### 7.3 演示环境注意事项

- Serverless 实例无状态：冷启动或重新部署后内存数据重置为种子数据，属预期行为。
- JWT 密钥在未显式配置 `JWT_SECRET` 时随实例随机生成，实例切换会导致旧令牌失效（重新登录即可）；生产环境必须显式配置。
- 演示模式开放 `/docs`（Swagger）与 `/api/meta`（演示账号列表），生产环境应关闭（`DEMO_MODE=false`）。
- 正式接入数据库时，使用 `database/init.sql` 初始化 MySQL 身份中心与 PostgreSQL 业务库，并配置 `MYSQL_URL`、`POSTGRES_URL`、`JWT_SECRET` 等环境变量。
