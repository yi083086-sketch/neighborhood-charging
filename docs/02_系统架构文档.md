# 系统架构文档

## 1. 架构原则

系统采用领域服务、事件驱动和 Agent 工作流结合的架构。身份、业务、记忆和审计分离，所有跨域调用通过明确的 API 或消息契约完成。Agent 不直接访问数据库，不执行任意 SQL。

## 2. 技术架构

```text
Web 工作台（HTML/CSS/JavaScript）
              │ HTTPS / REST / SSE
反向代理与安全层（Nginx/WAF）
              │
FastAPI API Gateway ── JWT/RBAC ── MySQL 身份中心
              │
领域服务：社区｜设备｜预约｜订单｜工单｜审批｜报表
              │                    │
      Redis/任务队列          PostgreSQL + pgvector
              │              业务事件｜审计｜短期记忆｜长期记忆
              └──── LangChain/LangGraph Agent
```

## 3. 数据边界

MySQL 保存租户、组织、用户、角色、授权和刷新令牌。PostgreSQL 保存社区运营业务、设备事件、订单、工单、审批、审计、Agent 运行记录及经过脱敏的记忆。Redis 保存短期缓存、分布式锁和异步任务状态。

## 4. Agent 工作流

```text
输入 → 意图识别 → 身份与数据范围校验 → 上下文检索
     → 工具规划 → 风险分级
        ├─ 只读：执行查询 → 结果校验 → 生成回答
        ├─ 普通写：幂等执行 → 回执校验 → 审计
        └─ 高风险：创建审批 → 人工决策 → 执行 → 回执 → 复盘
```

LangGraph 节点包括 `parse_intent`、`load_context`、`check_permission`、`plan_action`、`risk_gate`、`request_approval`、`execute_action`、`verify_result`、`write_memory` 和 `reflect`。

## 5. 可靠性设计

设备事件以事件编号唯一去重；预约和订单以业务幂等键防止重复创建；高风险执行使用审批编号和执行锁；数据库操作使用事务；异步任务支持重试、死信和人工补偿；健康检查同时检查数据库和任务队列。

## 6. 安全设计

接口统一使用 Bearer Token 和 RBAC；服务端再次校验社区和用户数据范围；Agent 工具采用白名单和 Pydantic 参数模型；模型输出不直接作为 SQL 或命令执行；对话、工具、审批和结果使用 trace_id 关联；日志禁止记录密码、令牌和完整支付信息。

## 7. 部署拓扑

生产环境由 Nginx 接入 HTTPS，FastAPI 以多进程运行，Agent 和事件处理使用独立 worker，MySQL 与 PostgreSQL 使用高可用或云数据库，日志和指标接入集中式平台。数据库、对象存储和密钥服务按企业现有基础设施部署。
