# 项目需求文档

## 1. 项目定位

邻里充电为多社区、多组织的充电网络提供统一运营能力。系统服务对象包括平台管理员、物业运营人员、维修团队、财务审批人员和居民用户，目标是提高设备可用率、预约成功率和故障闭环效率。

## 2. 业务目标

1. 统一管理社区、区域、车位、充电桩、枪口和计费规则。
2. 将预约、订单、设备事件、工单和审批形成可追溯业务链路。
3. 通过 Agent 降低人工查询和异常分析成本，但不绕过权限和审批。
4. 以多租户和审计为基础支持企业规模化运营。

## 3. 用户角色与权限

| 角色 | 核心权限 |
|---|---|
| 系统管理员 | 租户、组织、用户、角色、字典和系统配置 |
| 运营人员 | 社区、设备、订单、工单协同、运营报表 |
| 维修人员 | 负责设备状态、工单接单、维修回填和测试验收 |
| 财务/审批人员 | 退款、停机、调价和批量操作审批 |
| 居民用户 | 本人预约、订单、投诉、退款申请和设备查询 |

## 4. 功能需求

### 4.1 身份与组织

支持登录、令牌续期、退出、角色授权、社区范围授权和操作审计。用户数据由 MySQL 统一管理，业务服务不得复制密码。

### 4.2 设备与事件

管理社区、区域、充电桩和枪口；接收心跳、功率、电流、温度、离线和充电中断事件；支持事件幂等、状态机和告警升级。

### 4.3 预约与订单

用户查询可用设备、创建和取消预约，平台防止同一枪口时间冲突；订单状态包括待支付、已预约、充电中、已完成、已取消和异常；所有状态变化保留操作者和时间。

### 4.4 工单与维修

故障自动生成 P1/P2/P3 工单，支持分派、接单、处理中、待验收和关闭。关闭前必须完成设备心跳检查和测试订单验证。

### 4.5 Agent 工作台

支持自然语言查询、指标解释、故障归因、维修方案、订单分析和任务编排。Agent 必须返回数据来源、执行状态和 trace_id；停机、退款、调价、批量改派等动作只能创建审批申请。

### 4.6 审批与财务

审批流包含申请、风险评估、审批、执行和回执。审批记录包括影响范围、金额、业务理由、审批人、时间和执行结果，禁止重复审批和重复执行。

### 4.7 报表

提供设备可用率、利用率、故障率、平均修复时长、预约成功率、订单收入、退款金额和社区对比报表，支持日报、周报和异常复盘。

## 5. 非功能需求

- 关键 API P95 响应时间小于 500ms；Agent 查询首字节小于 5 秒。
- 支持水平扩展、健康检查、结构化日志和链路 trace_id。
- 所有写操作具备事务、幂等和审计；关键数据可恢复。
- 租户、社区和用户数据严格隔离；敏感字段脱敏。
- 生产环境采用 HTTPS、密钥管理、备份和灾备策略。

## 6. 验收标准

登录后只能看到角色允许的菜单；普通用户无法读取他人订单；重复设备事件不重复建单；高风险 Agent 请求生成审批而不直接执行；工单关闭必须完成验收；数据库故障时服务返回可识别错误并记录日志。
