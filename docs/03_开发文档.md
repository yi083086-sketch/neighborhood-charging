# 开发文档

## 1. 代码结构

```text
app/
├── main.py                 # 应用入口和路由
├── auth.py                # 令牌与角色依赖
├── config.py              # 环境配置
├── db.py                  # MySQL/PostgreSQL 连接
├── models.py              # ORM 模型
└── agents/graph.py        # LangGraph 工作流
static/                    # 企业运营工作台
 database/                 # 数据库初始化脚本
 docs/                     # 项目文档
 tests/                    # 自动化测试
run.py                     # 服务启动入口
```

## 2. 环境配置

复制 `.env.example` 为 `.env`，配置 `MYSQL_URL`、`POSTGRES_URL`、`JWT_SECRET`、`LLM_MODEL` 和 `LLM_API_KEY`。生产环境不得提交 `.env`，密钥由部署平台注入。

## 3. 本地开发

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python run.py
```

数据库初始化后，将 `DEMO_MODE=false`。接口文档仅供内部开发使用，生产环境应限制 `/docs` 的访问范围。

## 4. API 约定

所有需要登录的接口携带 `Authorization: Bearer <token>`。错误使用明确 HTTP 状态码：401 表示未认证，403 表示无权限，409 表示业务冲突，422 表示参数校验失败。写接口必须支持 `Idempotency-Key`，并在响应中返回 `trace_id`。

主要接口：

- `POST /api/auth/login`：登录并签发令牌。
- `GET /api/auth/me`：读取当前用户。
- `GET /api/piles`、`GET /api/orders`：设备和订单查询。
- `POST /api/device-events`：设备事件接入。
- `GET/POST /api/tickets`：维修工单管理。
- `GET/POST /api/approvals`：审批查询和决策。
- `POST /api/agent/chat`：Agent 工作流入口。
- `GET /api/dashboard`：运营指标。

## 5. Agent 工具规范

每个工具必须声明名称、输入模型、权限、数据范围、风险级别、幂等键、超时和审计字段。工具分为只读、普通写和高风险三类。高风险工具必须返回审批申请，不得在模型回复中假定执行成功。

## 6. 数据与记忆

短期记忆保存当前会话和最近工具结果，按租户和用户隔离并设置 TTL。长期记忆只保存脱敏后的稳定事实，经摘要、去重、权限过滤后写入 PostgreSQL/pgvector。禁止保存密码、令牌、完整身份证号和支付密钥。

## 7. 测试与质量门禁

```powershell
pytest -q
python -m compileall app
```

合并前必须通过认证、RBAC、租户隔离、预约冲突、订单幂等、事件去重、故障升级、审批拦截和 Agent 工具参数测试。生产发布前执行数据库迁移演练、备份恢复演练和压力测试。

## 8. 发布流程

代码审查通过后构建不可变镜像；执行数据库迁移；部署到预发布环境完成冒烟和回归；确认指标、日志、告警和回滚版本可用后再灰度发布。发布记录包含版本号、迁移号、变更内容和回滚方案。
